# 구조

## 한눈에

```
 차량                      신호 출처                 엔진(순수 Kotlin)              바깥으로
┌──────────────┐   ┌──────────────────────┐   ┌──────────────────────┐   ┌────────────────────┐
│ Pleos Vehicle│   │ SignalSource         │   │ CompanionEngine      │   │ SpeechController   │
│ NaviHelper   │──▶│  ├ PleosSignalSource │──▶│  구간 · 멈춤 이유      │──▶│  Pleos TTS → 기본 TTS│
│ FusedLocation│   │  └ DemoSignalSource  │   │  신호 반응 · 우선순위   │   │  오디오 포커스       │
│ AAOS Car API │   │   (체험 모드)         │   │  대본 엔진(고정 문장)   │   ├────────────────────┤
└──────────────┘   └──────────────────────┘   └──────────────────────┘   │ Compose 화면        │
                          VehicleState               EngineAction         │ (본문 3줄 + 버튼2)   │
                                                     EngineSnapshot       └────────────────────┘
                                   ▲                        ▲
                                   └──── TripController ────┘  (동행 한 번을 이끈다, 1초마다 onTick)
```

- `engine/` 은 안드로이드에 의존하지 않는 별도 Gradle 모듈입니다(Kotlin JVM). 안드로이드 클래스를 쓰면 컴파일되지 않습니다.
- 엔진은 시계를 갖지 않습니다. 모든 함수가 `nowMs` 를 받으므로, 같은 신호를 같은 순서로 넣으면 같은 말이 나옵니다(테스트로 확인).
- 신호 출처는 인터페이스 하나(`SignalSource`)이고 구현이 둘입니다. 체험 모드는 출처만 바꾼 것이라 엔진·음성·화면·저장은 같은 코드입니다.
- 그림의 '본문 3줄 + 버튼2'는 동행 화면 본문의 약속입니다. 화면 틀의 메뉴 5칸은 주행 중에도 함께 보이고 따로 셉니다(아래 '화면과 주행 규제').

## 엔진의 판단

### 구간(`StageCalculator`)

| 구간 | 조건 | 대본 상황 |
|---|---|---|
| 방금 출발 | 그 밖 | `depart` |
| 가는 중 | 10분의 1 이상 왔거나 출발 2분 경과 | `stage_onway` |
| 절반 | 10분의 4 이상 | `stage_half` |
| 거의 다 옴 | 4분의 3 이상이고 남은 시간 20분 이하 | `stage_near` |
| 곧 도착 | 남은 시간 5분 이하, 또는 근접 알림 | 남은 시간이 3분 넘고 5분 이하이면 `stage_5min`, 그보다 가깝거나 남은 시간을 모르면 `stage_near` |
| 도착 | 내비 도착 이벤트, 목적지 근처(아래 — 표본 2개 또는 10초로 확인, 근접 알림은 바로) + P단, 또는 운전자가 알림(`driverConfirmedArrival`) | `arrive` |

구간은 앞으로만 갑니다. 길을 다시 찾아 남은 시간이 늘어도 "절반" 뒤에 "가는 중"이라고 말하지 않습니다.
그래서 내비 표본 하나로 앞으로 가지 않습니다.

- 내비 남은 시간의 단위는 초입니다(2026-11-11 Pleos Connect 에뮬레이터: 9분 경로 = 540).
- 표본은 남은 시간·거리가 바뀔 때만 셉니다(정체 표시처럼 다른 칸만 바뀐 것은 새 표본이 아님).
- 남은 거리 0(또는 음수)은 경로를 찾는 순간의 기본값일 수 있어 도착 이벤트 없이는 받지 않고 앞의 값을 둡니다.
  남은 시간 0(또는 음수)은 남은 거리가 1~150m 이거나 도착 이벤트와 함께일 때만 받고, 아니면 그 표본을 버립니다.
- 내비 남은 시간으로 정한 구간은 같은 구간을 가리키는 표본이 2개 연달아 오거나 10초 이어질 때만 앞으로 갑니다.
  출발 2분·근접 알림처럼 표본과 상관없는 구간은 바로 갑니다.
- 목적지 근처도 시간과 거리를 서로 확인합니다: 남은 60초 안(남은 거리를 알면 300m 안일 때만 — 남은 2km 에 40초 같은 표본을 거름)
  또는 남은 거리 1~150m(남은 시간이 5분 안이거나 모를 때만). 이 판단도 표본 2개 연달아 또는 10초 이어질 때만 믿고, 그 상태로 P단이면
  도착입니다. 잘못 들어온 표본 하나로 "다 왔어요"를 먼저 말했다가 거두지 않게 하려는 것입니다. 근접 알림은 바로 믿습니다.
- 내비의 전체 시간이 크게 늘면(5분과 4분의 1 가운데 큰 것 이상) 새 경로로 보고 구간을 앞뒤 따지지 않고 다시 정합니다.
  되돌아간 구간은 따로 말하지 않고, 아직 말하지 못한 앞 구간 안내도 버립니다.

시간은 분 숫자가 아니라 구간 말로 전합니다. 분 숫자는 "5분쯤" 하나뿐이고, 남은 시간이 3~5분일 때만 씁니다.
주행 단에 넣으면 첫마디는 언제나 출발 안내(`depart`)입니다. 5분이 안 되는 짧은 길이어도 같습니다(그 구간은 확인되면 말없이 반영).
변속단과 주행 규제를 둘 다 모르면 시간만으로 출발했다고 하지 않고, 움직였다는 증거(속도 5km/h 이상)가 있을 때만 출발로 봅니다.

### 먼저 말해 주기 간격(`IntervalPolicy`)

자동 = 남은 시간의 1/6 을 4~10분으로 제한(남은 시간을 모르면 5분). 5분, 10분, 끔.
어떤 말이든 한 뒤로 간격을 다시 셉니다. 서 있는 동안과 '잠시 조용히' 중에는 하지 않습니다.

### 멈춤 이유(`StopClassifier`)

더 구체적인 사실이 앞섭니다: 도착 → 운전자 복귀 → 운전자 이탈 → P단 정차(경유지 / 도착인지 모름) → 정체 → 신호 대기.

| 이유 | 조건 | 다시 말하기 |
|---|---|---|
| 신호 대기 | 주행 단에서 서 있음 — 속도로 보면 20초, 브레이크로만 보면 35초 이상 | 쿨다운 60초, 계속 서 있으면 120초마다 |
| 정체 | 위와 같고 내비가 경로 정체를 알림 | 위와 같음 |
| 경유지 정차(`stop_waypoint`) | 출발한 뒤 P단 5초 이상 + 내비가 넉넉히 남았다고 함(5분 넘게, 남은 거리를 알면 1km 넘게) | 한 번 |
| 도착인지 모르는 정차(`stop_parked_neutral`) | 출발한 뒤 P단 5초 이상 + 그 밖(내비 정보가 없거나 곧 도착 구간). "차를 세웠어요. 따님이 알려 드릴 때까지 앉아 계세요." — 도착을 부정하지 않는다 | 한 번 |
| 운전자 이탈 | P단 + 운전석 문이 새로 열림 + 운전석 비움 + 동승 좌석 점유(들어설 때). 들어선 뒤로는 운전자가 돌아올 때까지 이어진다 | 75초마다 짧게(동승자 자리가 비어 있는 동안은 하지 않음 — 빈 차에 말하지 않고 횟수에도 넣지 않음). 다시 들어와도 30초 안이면 "내렸어요"를 되풀이하지 않음 |
| 운전자 복귀 | 이탈 뒤 운전석 점유 | 한 번(이탈을 알렸고 동승자가 자리에 있을 때). 출발한 뒤 내비가 넉넉히 남았다고 하는 정차면 "돌아왔어요. 다시 출발해요"(`driver_back`), 그 밖(내비 없는 길·곧 도착 구간의 정차, 출발 전)은 출발을 말하지 않는 "돌아왔어요. 편히 앉아 계세요"(`driver_back_parked`) — 바로 뒤에 '도착했어요'가 와도 어긋나지 않게 |
| 도착 | 위 표 | 한 번. 그 뒤로는 말하지 않음(아래처럼 거두기 전까지) |

- 좌석 점유 값은 2.5초 그대로일 때만 받습니다(흔들림 완충). 운전자가 돌아오면 다음 이탈은 운전석 문이 새로 열려야 봅니다.
- 운전자가 내린 동안 동승 좌석 문이 열리거나 자리가 비면 바로 "앉아서 따님을 기다려요"(안전 알림 우선순위, 10초 안 되풀이 없음)를
  말하고, 운전자가 돌아오면 "차에서 내린 사이 … 문이 열렸어요 / 자리가 비었어요"를 알림음과 붉은 한 줄로 1분 보입니다.
  문을 막지는 못합니다(안전장치가 아닙니다).
- 도착을 거둡니다(`ArrivalCancelled`): 도착 뒤 P단을 거쳐 다시 떠나면 — 속도를 알면 15km/h 넘게 달린 시간이 모두 30초, 모르면
  앞으로 가는 D단이 2분 이어질 때(후진·중립·P단이 끼면 처음부터. 내려 드린 뒤 주차 자리로 옮기는 것은 떠난 것이 아님. 도착 이벤트가
  굴러가는 중에 왔으면 P단을 볼 때까지는 재지 않음) — 또는 남은 시간으로 도착을 봤는데 같은 경로의 남은 시간이 1분 넘게 다시 늘면.
  운전자가 알린 도착과 새 경로(돌아갈 길을 넣음)는 남은 시간으로 거두지 않습니다. 거둔 뒤에도 운전자와 동승자가 함께 내려 차가 10분
  비면 동행을 마칩니다(아래 '동행 한 번의 흐름').
- 서 있을 때의 물음("언제 도착해?"·"다 왔어?"·"왜 안 가?")과 '다시 말씀드리기'는 그 정차의 말로 대답합니다. P단에 막 둔 때(정차 분류
  5초 전)도 정차의 말이고(내비 없는 길에서 "아직 가는 길이에요"라고 도착을 부정하지 않게), 방금 같은 말로 대답했으면 5초 뒤의 정차
  안내는 되풀이하지 않습니다.
- 내비 없이 가는 길은 차가 도착을 스스로 알 수 없어, 운전자가 알립니다(`driverConfirmedArrival`, 화면에서는 P단일 때
  `EngineSnapshot.canConfirmArrival`). 도착하면 어떤 경로로든 `Arrived(source)` 를 내어 도착 지점을 기억하는 계기로 씁니다.

'정지'는 속도 신호가 살아 있으면(한 번이라도 5km/h 이상) 속도 1km/h 미만으로, 아니면 브레이크 페달로 봅니다. 브레이크로만 볼 때는
서행 중·내리막에서 오래 밟는 것을 정지로 잘못 보지 않게 35초를 기다립니다(속도로 볼 때는 20초).
문 신호가 없는 차는 좌석 신호만으로 운전자 이탈을 보고, 좌석 신호가 없는 차는 이 기능이 꺼집니다.

### 신호 반응

| 신호 | 동승자에게 | 운전자에게 |
|---|---|---|
| 주행 중 문 열림 | 즉시(하던 말을 끊고) "문은 닫아 주세요" | 화면 + 알림음, 열려 있는 동안 15초마다 세 번, 그 뒤로는 60초마다 |
| 창문 30% 이상(설정 가능) | "손은 안에 두세요" 한 번(10%p 더 닫혔다 다시 열리면 또) | 화면 한 줄 |
| 안전띠 풀림 | 권유 2회(0초, 30초) | 60초 뒤에도 풀려 있으면 화면 + 알림음 |
| 운전자가 내린 동안 동승 좌석 문 열림·자리 비움 | 즉시 "앉아서 따님을 기다려요" | 돌아오면 화면 + 알림음(1분) |

운전자가 차에 있는 P단에서는 문·창문·안전띠를 알리지 않습니다(내리는 중일 수 있으므로).

### 우선순위와 쿨다운

`안전 알림 > 멈춤 > 대답 > 먼저 말하기`

- 통로가 비어 있으면(마지막 말이 끝나고 1.5초 뒤) 바로 말합니다.
- 누가 말하는 중이면 우선순위가 높을 때만 끊고 말합니다. 안전 알림은 다른 말을 기다리지 않고 끊습니다.
  안전 알림끼리는 끊지 않고 차례로 말합니다(문 안내가 창문 안내에 잘리지 않게).
- 운전자 화면의 알림은 상황마다 따로 두고 가장 급한 것 하나를 보입니다(주행 중 문 > 이탈 중 자리 비움·문 > 안전띠 > 창문).
  하나가 풀리면 남은 것이 다시 보입니다(문이 닫혀도 안전띠가 풀려 있으면 안전띠 알림).
- 그렇지 않으면 기다렸다가 말하되, 20초가 지나거나 그 사이 사실이 바뀌면(신호가 바뀌어 다시 출발) 버립니다.
- `잠시 조용히`(10분): 먼저 말하기·멈춤 안내·대답·창문과 안전띠 권유를 하지 않습니다(운전자 화면의 알림 한 줄은 그대로 나옵니다).
  주행 중 문 열림, 도착, 그리고 **운전자가 차에 없는 동안의 안내**는 합니다.
  `다시 말씀드리기`를 누르면 풀리고, 운전자 화면에 "잠시 조용히를 풀었어요."를 15초 보입니다.

### 대본 엔진

- 상황마다 변형 4개(운전자 알림과 카드는 2개)를 순서대로 돌려 씁니다. 무작위가 없어 재현됩니다.
- 빈칸은 `{호칭}`, `{곳}`, `{운전자}` 셋. `{운전자:이}` 처럼 조사 표기를 붙이면 받침을 보고 고릅니다(이/가, 은/는, 을/를, 과/와, 으로/로, 이에요/예요).
- 화제 전환 한마디(`redirect_*`)는 대답 두 번에 한 번 붙입니다. 대본의 화제 전환 줄도 `{호칭}, ` 으로 시작하므로,
  대답 뒤에 붙일 때는 그 호칭 부름을 떼어 한 번의 말에 호칭이 한 번만 들리게 합니다. 사용자가 직접 쓴 한마디도
  대본의 화제 전환 줄과 같은 검사(한 문장, 18음절, 금지어, 몸을 내밀게 하는 말, 병명)를 통과해야 읽습니다
  (`CompanionEngine.checkCustomPurposeLine` — 앱이 입력 때 불러 바로 알려 줄 수 있음).
- "집에 가자"(`ask_gohome`)는 "…에 들렀다가 집에 가요"로 대답합니다. 가는 곳이 집이면('집에서 쉬기'를 골랐거나 이름이 집·우리 집·댁)
  그 말이 맞지 않으므로 어디 가는지(`ask_where`: "집에 가요")를 그대로 말합니다.
- 동승자 카드 둘째 줄은 대본의 두 가지 꼴을 모두 받습니다: 구간별 상황(`card_stage_depart`·`onway`·`half`·`near`·`arrive`,
  서 있을 때 `card_stop`, 운전자가 내려 있을 때 `card_driver_away`) 또는 한 상황 `card_stage` 에 구간 순서대로 6줄.
  변형이 여럿이어도 첫째 것만 써서, 한 번의 이동에서 카드의 말투가 바뀌지 않습니다.

### 기록의 횟수(`TripCounts`)

- 엔진이 내보내는 말(`Speak`)마다 번호(`id`)가 붙고, 음성 쪽이 `onUtteranceResult(id, spoken)` 로 실제로 소리 냈는지 돌려줍니다.
  횟수는 소리 낸 말만 셉니다. 포커스를 얻지 못했거나 음성 엔진이 없거나 다른 말에 끊긴 말은 `skipped` 로 따로 셉니다.
- 안전 안내는 한 번의 일(문 한 번 열림 등)을 한 건으로 셉니다(되풀이 안내는 세지 않음).
- `spokenOnBehalf`(차가 대신 말한 횟수) = 먼저 말하기 + 다시 말씀드리기 + 물음 대답 + 멈춤 안내. 이 앱이 주장하는 것은 여기까지입니다.

### 대본 검사기(`ScriptValidator`)

| 규칙 | 내용 |
|---|---|
| R1 | 동승자에게 하는 줄은 `{호칭}` 으로 시작(화제 전환 줄 포함) |
| R2 | 한 문장 18음절 이하, 한 줄 두 문장 이하(화제 전환은 한 문장). 음절은 예시값(어머니·큰딸 집·따님)으로 채우고 부호·공백을 빼고 셈 |
| R3 | 금지어: 아까, 또, 다시 말, 말했, 말씀드렸, 기억, 몇 번, 왜 자꾸, 잊, 모르, 틀렸, 문장 처음의 아니에요 |
| R4 | 변형 둘 이상, 서로 다른 문장 |

앱에 들어가는 대본 파일 전체가 이 검사를 통과하는지를 단위 테스트가 확인합니다.
`ScriptExpansionTest` 는 대본 전체를 호칭 6개 x 운전자 5개 x 곳 4개(120가지, 14,160줄)로 펼쳐, 손으로 적은 정답표와 견주어
조사가 틀린 곳이 없는지와 한 문장이 18음절을 넘지 않는지를 봅니다(펼친 결과: `engine/build/josa-expansion.txt`).

새 대본으로 엔진 테스트 전체를 돌려 보려면 `./gradlew :engine:test -PscriptFile=<대본 파일>`.

## 화면과 주행 규제

| 화면 | 주행 중 | 내용 |
|---|---|---|
| 동행 중 | 열림 | 본문 글 세 줄(누구·어느 자리 / 어디·어느 구간 / 마지막 안내) + 큰 버튼 둘(`다시 말씀드리기`, `잠시 조용히`). 정차 중에만 아래 줄에 `도착했어요`(출발 뒤·도착 전)와 `동행 끝내기`가 더해짐 |
| 동승자 카드 | 열림 | 큰 글자 두 줄 |
| 출발 전 설정, 오늘의 기록, 환경설정, 개발자 패널 | **잠김** | 주행 규제 중에는 잠금 안내(글 두 줄·버튼 하나)만 보임 |

- 주행 규제 = `CarUxRestrictions`, 그 값이 없으면 변속단이 P 가 아닌지(둘 다 모르면 잠그지 않음, `DrivingLock`).
  화면 잠금은 지금 신호 출처의 규제 OR 실차의 규제입니다. 체험 모드를 켜고 실제로 달려도 실차 값으로 잠깁니다
  (체험 모드의 개발자 패널만은 모의 주행으로는 잠그지 않습니다 — 신호를 흉내 내는 도구라서).
- 화면 틀의 메뉴 5칸(출발·동행·카드·기록·설정)은 주행 중에도 함께 보입니다. '글 세 줄·버튼 둘'은 본문에 대한 약속이고 메뉴는 따로 셉니다.
  `ShellLayoutTest` 가 화면 틀까지 그려 셉니다: 본문 글 3줄, 본문 큰 버튼 2개, 메뉴 탭 5개(칸마다 짧은 글 한 줄), 누를 것 모두 7개,
  스크롤 0 — 가로 창과 세로 창(아래 메뉴) 모두. 급한 알림이 떠도 본문 글은 3줄 이하입니다.
- 첫째 줄 자리에는 앱 상태 한 줄이 대신 올 수 있습니다: "음성 엔진이 없어 화면으로만 알려요", "차량 신호가 없어 먼저 말하지 않아요",
  마지막 말을 소리 내지 못한 까닭("내비 안내 중이라 / 통화 중이라 / 다른 소리가 나는 중이라 소리 내지 않았어요"), "도착 안내가 끝나면 동행을 마쳐요".
  셋째 줄에는 하려던 말이 그대로 남습니다.
- 운전자 알림 한 줄(붉은 급한 알림 포함)은 셋째 줄 자리에 보입니다. 앱이 화면 뒤에 있으면(내비가 앞) 급한 알림만 안드로이드 알림(헤드업, 채널 소리 끔)으로
  한 번 띄우고, 진행 중 알림의 글도 그 한 줄로 바꿉니다(`TripNotifications`). 같은 일의 되풀이 안내로는 다시 띄우지 않습니다.
- 주행 중 화면에는 스크롤·움직이는 그림·긴 글·글자 입력이 없습니다. `도착했어요`·`동행 끝내기`도 정차 중에만 보입니다.
- 처음 실행 안내(정차 중에만): 안전·개인정보 안내, 차량용 기기에서 속도 권한이 없으면 속도 신호 허용을 한 번 권함(허용 창이 '위치 정보'로 뜬다는 것을 미리 말함).
- 넓은 창(가로)과 좁은 창(세로) 모두에 맞춥니다: 900dp 이상이면 왼쪽 메뉴, 아니면 아래 메뉴.
- 색은 밤·낮 두 벌이고, 글자 대비 4.5:1 이상을 단위 테스트로 검사합니다. 가장 작은 글자가 22sp 입니다.
- 버튼은 누르면 95% 로 줄고 바탕색이 바뀝니다.

## 차량 신호 연결(`AppContainer`, `PleosSignalSource`)

- 신호 출처: 차량용 기기면 실차 신호(`PleosSignalSource`), 환경설정에서 체험 모드를 켰을 때만 모의 신호. 차량용이 아닌 기기는 체험 모드로만 돕니다.
  차량용 기기에서 신호를 하나도 얻지 못하면 체험 모드로 넘어가지 않고 '차량 신호 없음'으로 돌며(환경설정과 동행 화면 첫째 줄에 알림),
  그때 엔진은 출발을 알 수 없어 먼저 말하지 않고 '다시 말씀드리기'에만 어디 가는지 대답합니다.
- 구독 수명: 화면이 보이거나 동행 중일 때만 구독합니다(`DrivingLock.shouldSubscribe`). 마지막 화면이 멈추고 1초 뒤 동행이 없으면 놓고,
  다시 보이면 붙입니다. 화면 없이 Gleo 로 시작한 동행도 붙입니다. 놓을 때는 리스너를 바로 풀고 SDK 는 기다리던 콜백이 돌아온 뒤에 놓습니다.
- 다시 시도 2·4·8초(세 번), 지원 영역에 든 자리만 등록, 속도 권한을 새로 받으면 Car API 만 다시 붙임(동행 중 좌석·문 값이 끊기지 않게).
- 좌석 점유 값 해석(`SeatValueReader`): 자동은 출발 전 설정(P단)과 동행 시작 순간의 운전석 값으로 그대로·반대로를 정하고 동행 중에는 바꾸지 않습니다.
  자세한 것은 `docs/signals.md` 1절.

## 동행 한 번의 흐름(`TripController`)

1. `start(config)` — 설정을 '자주 가는 길'로 저장, 엔진을 만들고 소개말, 포그라운드 서비스 시작. '물으면 대답하기'가 켜져 있으면
   음성 인식을 '말하는 중' 수집보다 먼저 시작해, 소개말을 말하는 동안 듣기가 멈춰 있게 합니다.
2. 신호가 바뀔 때마다 `engine.onSignals`, 1초마다 `engine.onTick`. 엔진이 돌려준 `EngineAction` 을 음성·알림음으로 옮기고 `EngineSnapshot` 을 화면에 냅니다.
   말마다 실제로 소리 냈는지(`SpeechResult`)를 `engine.onUtteranceResult` 로 돌려줍니다. 급한 운전자 알림은 진행 중 알림과 헤드업으로도 옮깁니다.
3. `confirmArrival()` — 운전자가 `도착했어요`(또는 Gleo `REPEAT_TRIP_ANSWER` 의 `arrived: true`)를 누르면, 주행 중이 아니고 엔진이 받을 수 있을 때만
   `engine.driverConfirmedArrival` 을 부릅니다. 도착 안내(`arrive`)의 결과가 오면(소리 내지 못했어도) 다음 1초 틱에 동행을 마치고, 30초 안에 오지 않아도 마칩니다.
4. `end()` — 엔진에서 횟수 기록을 받아 저장, 서비스 종료. 도착(`Arrived`)한 뒤 10분이 지나도 끝내지 않으면 스스로 끝냅니다.
   운전자와 동승자가 함께 내려 P단에서 운전석·동승 좌석이 모두 10분 비어 있어도(`EngineSnapshot.vacantSinceMs`) 스스로 끝냅니다
   (내비 없이 간 길이나 도착을 거둔 뒤에 동행이 남아 다음에 옛 가는 곳을 말하지 않게. 좌석 신호가 없는 차는 해당 없음).
   도착을 거두면(`ArrivalCancelled`) 그 예약도 풉니다. 도착 지점 기억은 `Arrived` 때 합니다(운전자가 알린 도착은 그때 위치로 새로,
   차가 본 도착은 저장된 지점이 없을 때만, 도착을 거두면 그 도착에서 저장한 지점을 되돌림).

포그라운드 서비스는 동행 중에만 떠 있고 부팅 때 스스로 시작하지 않습니다. 차량 신호는 리스너로 받습니다. 주기적으로 묻는 것은
동행 중 내비 정보(남은 시간은 콜백으로만 와서 30초마다 다시 물음) 하나이고, 엔진은 1초 타이머(`onTick`)로 시간을 셉니다.
